# Privacy Policy – B2R (Backlog to Redmine)

Last updated: 2026-09-20

## Overview

B2R helps users translate and synchronize work content between supported Backlog and Redmine environments. This policy explains what information the extension processes and how it is protected.

## Information processed

B2R may process the following information when the user activates the related features:

- Backlog and Redmine domains, project identifiers, issues, comments, links, work logs, and attachments needed for synchronization.
- Text submitted to the AI provider selected by the user for translation.
- Configuration values, language and theme preferences, and encrypted API keys stored locally in the browser.
- Diagnostic logs and optional screenshots when the user explicitly creates a bug report.

B2R does not sell user data, use it for advertising, or collect browsing history unrelated to the supported Backlog and Redmine workflows.

## How information is used

Information is used only to provide translation, synchronization, time logging, configuration, diagnostics, and update-checking features requested by the user. Data sent to an AI provider is sent directly to the provider selected and configured by the user, subject to that provider's privacy policy.

## Storage and security

Settings and API keys are stored locally using the extension's protected storage flow. API keys are not included in popup content or bug-report metadata. Users should revoke keys if they believe a credential has been exposed.

## Bug reports

Bug reports are local-first. The extension does not automatically upload reports or screenshots. The user chooses whether to download a report, copy it, or open a prefilled GitHub issue. Users should review and remove sensitive information before sharing a report or screenshot.

## Data sharing

B2R does not share data with the extension developer by default. Data is transmitted only to the Backlog, Redmine, AI, update, or issue-reporting service required by a feature the user explicitly uses.

## Data retention and deletion

Users can remove saved settings, API keys, logs, and bug-report data by using the extension's Options page or by removing the extension from Chrome. Data retained by third-party services is governed by their respective policies.

## Changes and contact

This policy may be updated when the extension's data practices change. For questions or privacy concerns, please open an issue at:
